## Slide overflow
- `sections/03-content.prose.md` § Starting a team in Claude Code — overflows because: too many ideas (a shell command block + a multi-clause freeform example prompt + two explanatory paragraphs on teammate context scoping and resume-restore behavior; four distinct units on one projected surface)
- `sections/03-content.prose.md` § Cross-module feature: an agent team — *estimate, borderline*: Why clause + three numbered steps + Expected result sentence + caveat on subagent sufficiency + link = five units; probably the last two sentences could move to the document register without loss on a slide

## Strengths
- `sections/03-content.prose.md` — the scenario/answer pairing (`## An unstable login session` → `## Login investigation: an agent team`) is the clearest structural choice in the presentation register; each question slide projects as one unresolved problem, the answer slide opens with the decisive criterion before listing steps, and the pair reads as a unit without requiring the prior slide to be on screen
- `sections/02-motivation.prose.md` — `delegation-collaboration.png` earns its place across all three registers: in the document it introduces both coordination patterns before the prose names them; on a slide it gives a clean full-bleed surface with no competing text; on the website the image self-describes the section without requiring the prose that follows
- `sections/04-conclusion.prose.md` § Failure modes and checks — the table survives all three renders; five short rows project cleanly on a slide, scan as a quick-reference checklist on the website, and read as a synthesizing summary at the end of the document
- `sections/01-context.prose.md` — headings are short navigable claims throughout; the three in this section (`Subagents and teams` / `What this tutorial covers` / `One task, several ways to work`) give a website visitor an accurate map of the opening before clicking into any of them

## Weaknesses
- `sections/02-motivation.prose.md` — `orchestrator-worker.svg` is built and never placed. The SVG shows exactly the structural difference the entire tutorial turns on: in the left panel, Workers A/B/C are isolated below the Orchestrator with the note "workers cannot see each other"; in the right panel the same layout gains red bidirectional arrows between workers labeled "direct messages between workers (teams only)." Every answer slide uses the phrase "each worker holds its own context" or "teammates exchange findings," but a reader finishes the tutorial without ever seeing those relationships drawn. The `delegation-collaboration.png` shows two arrangements side by side but does not label the isolation/communication contrast explicitly; `orchestrator-worker.svg` does exactly that and is already at production quality.
- `sections/02-motivation.prose.md` — four additional figures exist in `figures/` and are also unused: `failure-mode.svg` (context limit before/after), `single-agent-limit.svg` (single-agent serial bottleneck), `task-decomposition.svg` (orchestrator fan-out flow), and `context-workspace.png` (separate contexts, shared files). Together with `orchestrator-worker.svg` these represent substantial built investment with no placement. They are not all necessary — the tutorial does not need five more figures — but the gap between what was built and what appears in the prose is worth a deliberate decision rather than an accident.
- `sections/02-motivation.prose.md` — the heading `## Delegation and collaboration` names the figure, not the concept. In the website navigation it sits between `## What this tutorial covers` and `## When a subagent helps`; a reader scanning those headings reads the first as scope, the third as a decision criterion, and the second as a pointer to an image. Every other `##` heading in the file is a navigable claim; this one is not.
- `sections/03-content.prose.md` § Starting a team in Claude Code — the "Then ask:" block contains a full multi-clause natural-language prompt (authentication regression, teammate count, coordination instruction). On a slide it reads as a body-copy paragraph competing with the shell command for the reader's eye; the two items do not have the same visual weight and the longer one is harder to parse at projection distance.
